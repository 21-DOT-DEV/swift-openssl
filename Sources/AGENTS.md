# AGENTS.md (Sources)

This directory contains the library implementation: one Swift target and two C binding targets.

## What lives here

- **Swift target**: `OpenSSL` — idiomatic Swift API with top-level types (`SHA256`, `RSA`, `SSL`, `Base64URL`, `OpenSSLError`). Manually maintained.
- **C binding target**: `libcrypto` — raw bindings to OpenSSL's crypto library, extracted from vendored upstream plus Configure-generated headers.
- **C binding target**: `libssl` — raw bindings to OpenSSL's SSL/TLS library, extracted from vendored upstream.

## Extractions

`Sources/libcrypto/` and `Sources/libssl/` are generated by extraction from `Vendor/openssl/`. Before making changes here, check `subtree.yaml` to confirm the extraction mapping and avoid unintended divergence that will be overwritten on the next extraction.

- `Sources/libcrypto/include/openssl/` — public headers (`openssl/*.h`); exposed in the C module
- `Sources/libcrypto/internal_include/` — internal + crypto private headers; accessed via `headerSearchPath`, NOT in the module map
- `Sources/libcrypto/providers/` — provider headers and implementation sources (`providers/**/*.c` + `.h` + `.inc`)
- `Sources/libcrypto/src/` — core crypto sources (`crypto/**/*.c` + `.h`)
- `Sources/libssl/src/` — SSL/TLS protocol sources (`ssl/**/*.{c,h}`)

See `Vendor/AGENTS.md` for the Configure-generated files that appear under `Sources/libcrypto/` but are NOT in upstream `Vendor/openssl/`.

## Header search path layout

`libcrypto`'s `cSettings` declares four header search paths — order matters, they are searched in declaration order:

1. `include` — public headers (`<openssl/xxx.h>`)
2. `internal_include/include` — quoted includes `"crypto/xxx.h"` and `"internal/xxx.h"`
3. `internal_include` — provider-style quoted includes `"include/crypto/xxx.h"`
4. `src` — local headers like `"crypto/xxx/xxx_local.h"`
5. `providers/providers/common/include`, `providers/providers/implementations/include`, `providers/providers/fips/include` — provider headers (e.g., `"prov/xxx.h"`, `"fips/fipsindicator.h"`)

If you add a new extraction path to `subtree.yaml`, ensure its header search path is wired up in `Package.swift` or the C sources will fail to resolve `#include`s.

## Non-obvious patterns

- **Excluded from build**: `libcrypto` excludes two files that are `#include`d by other sources (not compiled separately): `src/crypto/LPdir_unix.c` (included by `o_dir.c`) and `src/crypto/des/ncbc_enc.c` (included by `cbc_enc.c`).
- **Runtime fallback directories**: `libcrypto` defines `OPENSSLDIR` / `ENGINESDIR` / `MODULESDIR` via `cSettings.define(...)`. These are returned by `ossl_get_*dir()` as defaults; changing them affects X.509 cert paths, engine loading, and provider loading.
- **`_GNU_SOURCE` on Linux only**: Required for glibc features like `pthread_rwlock_t` and full POSIX support.
- **`OPENSSL_NO_ASM` on libssl**: Matches the Configure flag. All assembly sources are excluded in `subtree.yaml`.
- **Top-level types in `OpenSSL` target**: Constitution Principle IV forbids namespace enums. `SHA256`, `RSA`, etc. are module-scope, matching swift-crypto. Do NOT nest public types inside `OpenSSL.*` enum namespaces.
